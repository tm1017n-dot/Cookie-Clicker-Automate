# alpha.13 分割測定と長期目標経路

作成日: 2026-09-25。alpha.12からの状態取得軽量化と購入戦略拡張。

## 状態取得

Gameの仮想状態で実行する`CalculateGains`を、1回の状態取得につき最大4回へ制限する。

- Buffを除いた基準値とCursorを優先して測る。
- Thousand fingers系を所持する場合は、クリック寄与を求めるため最初の非Cursor施設も測る。
- その他の通常施設は`storedCps`と監査済みのSynergy・Kitten・施設実績モデルで評価する。
- 効果モデルがないUpgrade、購入可能なUpgrade、安価なUpgradeの順で測定し、上限を超えた分は同じ状態の次周期へ送る。
- 残件はUIと診断JSONへ表示する。残件があることを効果不明と混同せず、`measurement-pending`として記録する。

これにより、施設やUpgradeが増えても1周期の同期測定回数は増え続けない。状態が変わらない間は測定済み結果を再利用する。

## 長期目標

近距離のBeam探索は3手のまま維持し、それとは別に解禁目標への決定的経路を評価する。

- 各施設について次の2段階の通常Tier Upgradeを候補化する。
- 次の3段階のKittenを候補化する。
- SynergyとResearchを従来どおり候補化する。
- 目標経路は最大512行動、全候補合計1024行動まで評価する。
- 各施設購入は価格上昇、購入までの収益、購入後の生産増加、途中の施設実績とMilk増加を順番に反映する。
- 経路候補は現在の予約、必要施設数・実績数、価格の順で評価し、近い目標が遠い目標に探索予算を奪われにくくする。
- 長期経路を選んでも実行するのは先頭1購入だけで、次周期に再計画する。

単純に探索深度を増やして全購入順を分岐させる方式ではない。短期の買い順は詳細探索し、遠いTier・Kitten等は目標ごとの一本道として比較する。

## 検証

自動試験146件、配布ビルド、全JavaScript構文、純粋層検査に合格した。

- 状態取得が4回を超えて`CalculateGains`を呼ばない。
- 同じ状態の後続周期で残りのUpgrade測定を完了し、完了後は0回になる。
- ロック中施設を測定しない。
- 40施設購入と最後のUpgrade購入からなる41行動の経路を完走する。
- 将来のKittenを3段階まで候補化する。
- alpha.12診断を保存版Plannerで再生する。

ユーザー指示に従いブラウザ検証は実施していない。通常施設の未登録特殊効果は個別測定でなく監査済みモデルへ依存するため、新しいゲーム版へ対応する際はモデルと公式実装の再監査が必要になる。
