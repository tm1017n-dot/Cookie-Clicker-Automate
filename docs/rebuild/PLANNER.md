# 購入・待機プランナー詳細設計

設計版1.0。純粋関数plan(PlannerInput)の規則。未知効果・時間不足を購入強制で隠さない。

alpha.4追記：[購入戦略変更設計](STRATEGY_ALPHA4.md)により、次Tierの解禁経路、一手比較を基準にしたモデル範囲の公平化、3回の優位確認後の予約切替を追加した。以下の「自動的な目標切替は追加設計後」という初期方針は、この追加設計で具体化済み。

## 1. 目的と資産

初期目的は成長。通常運転は将来の経済資産、明示目標がある場合は目標到達時間も保持する。転生助言は次周回を含む別の候補経路として同じPlanner内で比較する。

資産は bank（即時使用可能）、deferred（虫など未回収）、inventory（換金費用控除後）、earnedProgress（ゲームの累計生産更新規則）に分ける。deferred/inventoryを所持金ETAへ足さない。

時刻tの流動収益L(t)=passiveLiquid(t)+mouseCps(t)*effectiveClickRate(t)。
経済収益E(t)=L(t)+deferredGrowth(t)。クリック寄与を二重加算しない。
Buff期間内外でmouseCps自体を計算する。Frenzyを全クリックに単純乗算しない。

## 2. 期待資産の計算

各シナリオについて:
- B(H)=B(0)+integral[0,H] L(t)dt + 一時報酬 - 購入費 - 手数料 - 頭金。
- A(H)=B(H)+H時点で回収可能な資産の純額。
- V(H)=E[A(H)]+R_unlock(H)+R_combo(H)-Risk(H)-OutstandingCost(H)。

待機中にも収益を加える。購入がHより後なら、その期間内では費用も購入後効果も計上しない。即時購入可能なのに待機を常に有利にする「支出だけを数える」実装や、待機前収益を落とす実装を禁止する。

RはHより後の未計上効果の保守的な残存価値であり、経路内の報酬を再加算しない。根拠あるモデルがないRは0とし、価値不明の印を残す。ローン反動等の確定債務は期間外でもOutstandingCostへ含める。

Riskは既知確率分岐の下振れ指標。初期は0.1*max(0,平均A-下位10%点A)。これは攻略上の確定値ではなく調整対象パラメータ。推定信頼度の低さは別のuncertaintyとして区間表示し、根拠のない確率へ変換しない。

## 3. 共通評価期間

固定900秒だけでは回収の遅い投資を永久に見送るため、各周期に全候補共通の期間を選ぶ。

- 基準はH1=60、H2=300、H3=900秒。
- 時間非依存の対応済み収益候補/解禁経路について、最小の正の「資金到達時間+回収時間」をTとする。
- H3=max(900,4*T)、H2=max(300,H3/3)。Tが不明なら基準期間を使い、horizon-incompleteを記録する。初期案の2*TはTIME-03で先送りが残るため修正した。詳細は[実装記録](IMPLEMENTATION.md)。
- 予約対象の既知の到達時点がH3外なら、その時点と回収を含む期間まで全候補共通で延長する。
- Buff、研究、魔力等は延長期間でもイベント境界で計算する。現在Buffの永続外挿は禁止。
- 遠い未来の不確実性は確率/モデル警告へ表し、Game API例外や未知モデルを大きな利益で埋めない。

この期間規則は初期設計仮説であり、最適性の証明ではない。全候補で同じ期間を使い、期間感度試験で先送り・過剰貯蓄を検出する。固定最大待機時間による候補除外は行わない。

## 4. Action生成

施設1個、全ストアUpgrade、無条件wait、資金到達wait、次イベントwait、対応済み解禁/コンボの先頭操作を列挙する。

候補参加をpriority/critical/価格順位で制限しない。設定禁止・権限不足・未解禁・未知価格は理由付きの不適格状態として診断一覧へ残す。未知効果Upgradeも残し、追加の証拠取得を次周期へ要求する。

将来目標は前提DAGから生成する。施設Tier、施設実績、Milk/Kitten、Synergy、Research、ミニゲーム資源解禁を対象とする。経路費用は各段階で価格/生産を更新し、最終Upgrade価格だけで解禁価値を評価しない。

未知効果だけが残る状態ではWAIT_UNKNOWN_EFFECTと再観測を返す。「効果不明の候補を残す」は「適当な増産を与えて買う」を意味しない。

## 5. 状態遷移と時間

advance(state,seconds,scenario)は次の既知イベントまで区分積分する。Buff終了、研究完了、魔力/礼拝回復、季節終了、ローン反動、成熟/枯死、資金到達を扱う。

apply(state,action,outcome)は費用、施設/Upgrade、実績、Milk、解禁、資源を更新して次の候補を再生成する。価格割引・Synergy・クリックCpS依存・施設数閾値を再評価する。モデルが非対応の子ノードを根の差分で外挿しない。

未来のGCや作物成長は決定的な「必ず来るイベント」にしない。能力に応じた固定シナリオ集合で扱い、全候補に共通乱数を使う。自然GCとFtHoFの分布を共有しない。

## 6. Paretoと探索

1. 全合法候補の単独購入/待機経路を評価する。wait→購入もひとつの経路として評価する。
2. 短中長V、各目標ETA、資金不足リスクを保持する。早期に単一スコアへ潰さない。
3. すべての比較軸で劣る経路だけをPareto除外する。不明値同士を劣位認定しない。
4. 2～3手のBeam探索を実施する。waitは時間を進め、購入/資源操作を実手数として数える。
5. 予約対象、合法な先行投資、wait、各目標の先頭経路を保護枠とする。Upgrade固定優遇枠は設けない。
6. 最終frontierで戦略重みを適用し、先頭1操作と予約遷移を返す。

初期上限: depth=3、beamWidth=24、展開node=1024、各経路event=4096。根の全候補は診断する。保護枠が上限を超えるときは予算超過を明示し、予約対象とwaitを優先して安全に縮退する。未展開候補が最適でないとは主張しない。

中間Beam選択は多様性のため各評価軸の極値→目標経路→安定ID順のround-robinを使う。最終戦略重みを途中の単一選別器にしない。ゼロ時間wait、同状態再訪、達成済み目標の循環を禁止する。

同点は eps範囲→同じ目的で先頭支出が少ない経路→Action ID辞書順で処理する。価格は同点処理だけに使う。

## 7. 戦略重み

V(H)-無操作基準A0(H)を、候補非依存の D(H)=max(1,abs(A0(H)),B(0)) で割って各期間を正規化し、最後に重み付き和を取る。初期値は短期0.20、中期0.35、長期0.45。

COMBO_PREPでは期間重みだけで操作を強制しない。次コンボの資源/流動性を満たす経路を別シナリオで評価し、加算する残存価値と経路実現利益を区別する。戦略プロファイルと重みは入力に含め、テストと変更履歴の対象にする。

paybackは候補説明、期間決定、診断用の共通指標であり、別レイヤーで勝者を上書きする命令ではない。ROIだけで最適な購入順が決まるとは仮定しない。

## 8. 予約と先行投資

予約は選択経路の資金不足目標を保持する。stateはnone / saving / ready / pending / blocked / completed / invalidated。

- saving: 目標への直接ETAと、今買える各候補1件購入後の同目標ETAを同じ時間モデルで計算。
- 先行購入は、費用・購入後生産・変わった目標価格・保護額を含めてETAが許容差より短い場合だけ合法。
- 改善候補の中から共通価値で先頭1件を選ぶ。なければWAIT_TARGET。
- ready: 目標だけを試行する。他施設の価格が安くても無関係。
- pending / rejected / exception: 対象を保持し、当該周期は別操作しない。
- confirmedかつ目標取得: completedへ進む。先行購入成功では予約を解除しない。
- 目標が手動取得済み、設定で禁止、転生で消滅、前提が成立不能と確認された場合のみ理由付きでinvalidated。
- 状態取得エラーや一時的なストア反映遅延は成立不能の証拠にしない。blockedとして再観測する。

定率・価格固定の場合の検証式:
direct=max(0,Ptarget+reserve-B)/L
via=max(0,PtargetAfter+reserveAfter-(B-Ppurchase))/Lafter
待ちが必要な先行購入、Buff終了、報酬分岐がある場合はこの簡略式を使用しない。

長期固定予約が経済状態変化に追随できないリスクは診断する。初版では「別目標の方が良さそう」だけで予約を解除せず、ユーザーの目標解除を提供する。自動的な目標切替は既存予約保証を壊さない追加設計・検証後に導入する。

## 9. 縮退と決定性

通常候補生成の一部失敗時は残った有効候補を同じ評価へ渡す。探索だけが上限到達した場合は、同じ関数の単独経路評価へ縮退する。価格順や独立ROI購入関数を追加しない。

Game API例外が当周期で起きた場合は購入しない。次周期の再取得が成功すれば評価を再開する。純粋な候補生成の局所失敗と、実状態の信頼性喪失を区別する。

実時計による探索打切りを通常の判断に使わない。固定上限・同一seed・同一Rulesetから同じ結果を返す。UI保護用watchdogが必要になった場合はその周期を未完了として操作せず、次周期の縮退モードを入力に記録する。

## 10. 実装前から保持する限界

未知効果、長期コンボ予測、探索予算により大域最適性は保証しない。予約中の完全停止、未知Upgrade放置、評価期間による逆転を専用診断にする。期待値だけでなく下振れと目標到達率を [VALIDATION](VALIDATION.md) で測る。
