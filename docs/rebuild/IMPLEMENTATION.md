# 再構築版 9.0.0-alpha.1 実装記録

## 9.0.0-alpha.5 未評価候補・負荷の改善

詳細は[追加設計と検証](PERFORMANCE_ALPHA5.md)。engineは9.0.0-alpha.5、rulesetはbasic-3。

- 未対応効果の候補が1件あるだけで待機理由を上書きする問題を修正。現在購入可能な未評価候補と、採算上の待機を区別する。既知候補の購入を未知候補で止めない。
- パネルに未評価・購入対象外の強化名と理由を一覧表示。購入可能な未評価候補があり待機する場合は一覧を自動で展開する。
- 通常Cookieの定数powerを測定照合した倍率として先読みする。施設割引・Upgrade割引を別々に反映し、丸め前価格と卵の価格増加も保持。任意の購入コールバックは仮想実行せず、ストア更新代入だけの処理を厳密に確認して許可する。
- 可変部分だけの状態コピー、対象候補の直接取得、親ノードからの末尾価値更新で重複計算を削減。クリック寄与の測定を既存測定にまとめ、対象外操作の仮想増産測定を省く。
- 自動試験103件、配布ビルド・構文検査が合格。alpha.4保存版を用い40合成状態の購入判断・予約・各探索値を比較した。旧版診断JSONは旧エンジンへ振り分けて再生する。
- 同じ25候補・41展開・20解禁経路の合成入力を各10回測定し、Planner中央値94.27ms→3.12ms。Node 24.19.0のローカル結果であり、Game観測・保存・画面描画を含むブラウザ全体の速度ではない。

ユーザーの報告状態はUIから対象を特定できず、診断未取得のため完全再現ではない。GC頻度・研究等の間接効果、価格関数や実績・相乗効果の将来変化には未対応が残る。測定限定候補との公平比較により、割引経路などを保守的に見送る場合もある。ブラウザ検証は指示どおり行っていない。

## 9.0.0-alpha.4 購入戦略の三点改善

詳細は[追加設計](STRATEGY_ALPHA4.md)。固定購入順は追加していない。

1. **解禁経路**：通常施設の次TierをGame.TiersとtieredUpgradesから取得する。従来のbuildingTie1判定で通常Tierまで測定限定とされていた点を修正。必要施設の一個ごとの値上がり、前提Upgrade、待機中の収益を含む完成経路を計算する。採用時は最終Upgradeを目標に保持し、一周期一操作。実ストアへの出現前は購入APIを呼ばない。
2. **予約見直し**：資金待ち中の予約を現在の状態で再評価する。正規化スコア差が0.05かつ旧スコア絶対値の25%を超える状態が同じ代替目標で3回続けば切替。4周期の再切替抑制、購入可能な既存予約・pendingの保護を設ける。微差や一時的な逆転で切り替えない。
3. **比較条件**：全候補の一手価値と追加探索の価値を分ける。測定限定候補に一手比較で負ける先頭操作は、深い探索だけを根拠に逆転採用しない。保留された経路と理由も診断へ残す。

新しい診断項目はunlockPaths、singleStepNodes、comparison、reservationReview、候補のoneStepHorizons/additionalValue。画面の詳細欄でも解禁経路と予約見直しを確認できる。

engineは9.0.0-alpha.4、rulesetはbasic-2。旧実測JSON5件は一切変更していない。旧エンジンをscripts/legacy/alpha1に保存し、CLIのreplay-engineが版に応じて振り分ける。旧実測を新版で再計算する性能比較は「旧判断の完全再生」と区別する。

自動試験86件、ビルド・構文検査を実施。Node 24.19.0のローカル比較では既存5入力の中央値約1〜15ms、合成の次Tier入力は約94ms（25候補・41展開・20経路）。入力依存の参考値であり、ブラウザ性能や長時間攻略の改善率を保証しない。ブラウザ検証はユーザー指示により未実施。

限界：実ゲーム接続が生成する未解禁候補は各施設の次の通常Tier。Synergy、Fortune、Milk実績等の将来解禁はまだ含まない。経路は24購入・全体256購入の予算内で評価し、未評価理由を記録する。測定限定候補に対する公平性は保守的で、本当は有利な長期経路を保留する場合がある。各閾値は初期値であり大域最適性は保証しない。

## 9.0.0-alpha.3 操作パネルとクリック制御

- タイトルのドラッグと矢印キーで移動、右下でサイズ変更。折りたたみ、位置を戻す操作を追加。位置・サイズ・折りたたみ状態をローカル保存し、画面外へ出ないよう補正する。保存が使えない場合も操作は継続する。
- クリック目標の初期値100回/秒、画面から1〜100の整数で調整可能。速度の変更は当該起動中に有効、自動化の有効状態は従来どおり保存しない。
- Web2.058のClickCookieは20ms未満の呼出しを拒否するため、50回/秒を超える設定時のみlastClickの待ち時間を調整し、通常のクリック関数を一回呼ぶ。Cookie数やクリック報酬の直接加算はしない。拒否時は元の待ち時間へ復元する。
- 成功したクリックだけを計測。観測モードの表示は0回/秒。開始直後も設定値を収益の仮値として用いず、初回から実測値で評価する。非表示タブや処理遅延の未実行分をまとめて連打しない。実速度は端末やブラウザ負荷に左右される。
- 固定の序盤購入手順は使わない。全時点で同じPlannerが施設・Upgrade・待機を比較する。たとえば施設0・所持金100の合成状態では、実クリック0回/秒ならGrandma、100回/秒ならCursorを選ぶ。Upgrade IDによる効果式はゲーム規則のモデルであり、取得順を命令するものではない。
- 速度変更・予約解除時に世代番号を進め、診断保存待ちだった古い判断から購入しない。変更後は新しい条件で再評価する。
- 状態表示を日本語の説明にし、目標と実クリック数を分けて表示。詳細JSONは必要時のみ描画する。

自動試験67件、構文検査、配布物ビルドを実施。ユーザー指示により、追加改善後のブラウザ検証は行わない。100回/秒は設定目標であり、実機で100回を確認済みとは扱わない。以後もブラウザ確認は明示依頼時だけ実施する。

## 9.0.0-alpha.2 不具合対応（2026-09-23）

新規開始時のbuilding:8予約と、実クリック約2回/秒・ブラウザ高負荷の報告を受けて修正。報告時の診断JSONは未取得であり、building:8の選択周期自体はまだ再現できていない。

- 観測中の提案を実行予約として保存しない。自動化開始時に予約をクリアし、新しいクリック条件で再評価する。保存待ち中のモード変更も世代番号で検出し、古い判断から購入しない。
- セーブ開始日時・通算開始日時・転生回数の変化で、前セーブの予約と未確定購入を破棄する。購入直前の署名にもこの識別情報を含める。
- 状態復元は変化した項目だけを書き戻す。公式2.058のCalculateGainsを再監査し、測定で変更されるGame本体・施設・生産内訳・対象Upgradeを保存対象に限定。以前不足していたcookiesPsByType/cookiesMultByTypeも復元する。
- 配布物はGM APIを使わないため `@grant none` とし、ゲームと同じ実行環境で動かす。閉じた詳細欄のJSON描画を省略する。
- 診断へcaptureMs/plannerMsを追加。分離した公式ゲーム環境の同じ所持施設で状態測定約462ms→約48msを観測。これはサンプル比較であり、ユーザー環境やTampermonkey拡張での性能保証ではない。
- 自動テスト60件合格。判断エンジンの仕様はalpha.1を維持し、既存の実測JSON5件も引き続き同一判断で再生可能。配布/runtimeの版はalpha.2として別に記録する。
- 修正版の専用新規セーブで観測モードを約1分継続してから開始。Cursor→Upgrade ID 0→ID 1を購入し、実クリック約19.2回/秒を確認。保存した71周期でcaptureMsの最大値は約62.7msだった。

旧alpha.1を置き換えてページを再読み込みする。旧版の予約は引き継がない。旧版で開始したまま「予約解除」を押すだけでは、測定負荷の修正は適用されない。

2026-09-23。設計ブランチを基点とした `feat/rebuild-engine`。v8.5の購入ループを流用せず、純粋な判断、Game接続、購入実行、診断保存、画面を分離して実装した。これは基本購入のアルファ版であり、M1〜M7全体の完成版ではない。

## 攻略アルゴリズムで見直した点

短中長期間を60/300/900秒だけに固定すると、遅い投資を永久に見送る。設計初期のH3=2Tも、重み0.20/0.35/0.45で短中期の支出損失を含めるとTIME-03で先送りが残った。そのため共通H3をmax(900,4T)へ修正した。最適性の証明ではなく、回帰試験に基づく初期値である。

CpSに比例するクリック増分を一度だけ計上する。Cursor強化などの再利用可能な倍率モデルもGame測定値と照合し、加算ボーナス等で一致しなければ根の一手のみの測定効果に切り替える。建物価格は丸め前価格と無料個数を保持する。施設Tierの回収比較をGrandmaとFactory双方で試験する。

- ビルド、分割ソースと配布物の構文検査。
- 公式main.js 2.058をlocalhostの専用テストページで動かし、通常セーブと別の保存キーを使用。新規0 Cookiesから自動クリックと購入を実行した。

## 開発・再生

```sh
node --test
node scripts/build.mjs
node scripts/check.mjs
node scripts/replay.mjs path/to/diagnostics.json
```

`scripts/live-server.mjs` は開発用の分離スモーク環境で、配布userscriptからは参照しない。実行にはリポジトリの親ディレクトリに公式main.jsを `game-main.js` として取得しておく必要がある。ゲームの画像・翻訳等は公式配信に依存する。公式コードは本リポジトリに同梱しない。
