# 再構築版 9.0.0-alpha.1 実装記録

2026-09-23。設計ブランチを基点とした `feat/rebuild-engine`。v8.5の購入ループを流用せず、純粋な判断、Game接続、購入実行、診断保存、画面を分離して実装した。これは基本購入のアルファ版であり、M1〜M7全体の完成版ではない。

## 導入

1. ゲーム自身のセーブをエクスポートする。
2. 旧Cookie Clicker自動化スクリプトをすべて無効化し、ゲームを再読み込みする。特にv8.0以前の匿名タイマーは新版から確実に停止できない。
3. `dist/Cookie_Clicker_Auto_Rebuild.user.js` をTampermonkeyへ追加する。分割ソースを個別に貼り付けない。
4. 初回は観測モード。画面の候補・診断を確認し「自動化を開始」を押す。
5. 停止・旧版へ戻す場合は新版を停止、無効化して再読み込みしてから旧版を有効化する。

対象はWeb版2.058、Modなし、通常周回。毎回観測モードから開始し、自動化の有効状態は永続化しない。旧設定の読み込みや削除は行わない。操作パネルは日本語だが、判断は内部IDに基づく。

## 実装した範囲

- ES Modulesの純粋Planner、JSON入力検証、三期間評価、待機中の収益、Buff終了・既知イベントの区分計算。
- 全施設・全ストアUpgradeの候補記録、未知効果の保持、Pareto比較、最大3手・1024ノードの決定的探索。
- 予約対象への直接ETAと先行購入後ETAの比較。実行は毎周期一件、失敗直後の別候補購入なし。
- CalculateGains測定と状態復元、現在状態と再利用モデルの照合、未知の子状態への外挿停止。
- 購入直前の所有権・状態・価格・資金チェック、取得結果の確認、未確定時の再購入抑止。
- 実クリック頻度の計測、通常Golden Cookie回収、単一起動、診断JSON保存・SHA-256・オフライン再生。
- 依存パッケージなしの単一userscript生成とCI定義。使用環境Node 24.19.0。外部依存がないためlockfileは不要。

## 攻略アルゴリズムで見直した点

短中長期間を60/300/900秒だけに固定すると、遅い投資を永久に見送る。設計初期のH3=2Tも、重み0.20/0.35/0.45で短中期の支出損失を含めるとTIME-03で先送りが残った。そのため共通H3をmax(900,4T)へ修正した。最適性の証明ではなく、回帰試験に基づく初期値である。

CpSに比例するクリック増分を一度だけ計上する。Cursor強化などの再利用可能な倍率モデルもGame測定値と照合し、加算ボーナス等で一致しなければ根の一手のみの測定効果に切り替える。建物価格は丸め前価格と無料個数を保持する。施設Tierの回収比較をGrandmaとFactory双方で試験する。

## 検証

- 純粋ロジック、Gameモック、失敗注入、100回の決定性比較、実測JSON再生の自動試験55件が合格。
- ビルド、分割ソースと配布物の構文検査。
- 公式main.js 2.058をlocalhostの専用テストページで動かし、通常セーブと別の保存キーを使用。新規0 Cookiesから自動クリックと購入を実行した。
- 自然進行でCursor1個→Upgrade ID 0→ID 1を確認。その後ID 2、Grandma、Farm、Mineの取得を確認した。Cookieの手動付与はしていない。
- 実際の購入記録5件を `tests/fixtures/captured/` に保存し、同一判断の再生試験へ追加した。元のユーザーセーブではなく、この専用新規セーブの測定値である。
- 同ページへの新版再注入後、パネル一個・観測モード・新周期開始を確認。タイマーの所有権拒否はGameモックでも検証した。

実ブラウザ検証は公式コードを使った分離環境であり、公式サイト上のTampermonkey拡張機能そのものの導入試験ではない。日英差は自動試験で検証、今回の自然進行スモークは英語。Grandma28・Factory境界は合成fixtureであり、報告時の実セーブを再現したとは扱わない。CIは定義を追加した段階で、GitHub上の成功を未確認。

## 開発・再生

```sh
node --test
node scripts/build.mjs
node scripts/check.mjs
node scripts/replay.mjs path/to/diagnostics.json
```

`scripts/live-server.mjs` は開発用の分離スモーク環境で、配布userscriptからは参照しない。実行にはリポジトリの親ディレクトリに公式main.jsを `game-main.js` として取得しておく必要がある。ゲームの画像・翻訳等は公式配信に依存する。公式コードは本リポジトリに同梱しない。
