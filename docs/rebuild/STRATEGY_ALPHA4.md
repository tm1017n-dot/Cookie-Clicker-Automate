# alpha.4 購入戦略変更設計

対象は通常購入の三点改善。固定の序盤手順は追加しない。ブラウザ確認はユーザーの明示依頼時のみ。

## 解禁経路

公式2.058のGame.Tiers.unlock、building.tieredUpgradesとUpgradeの対応を用い、各施設の次の未解禁・未購入の通常Tierを候補へ追加する。特殊Tier、Synergy、Fortuneは通常2倍と推測しない。Cursorの特殊な解禁条件は既存の監査済みモデルを維持する。店頭候補はすべて保持する。

純粋Plannerは前提Upgradeと必要施設の依存をたどり、一個ずつ価格・収益・経過時間を更新する。循環、未対応効果、無収益、経路手数予算超過を理由付きで棄却する。完成Upgradeだけでなく前提購入の全支出と待機収益を計上する。最大24購入/経路、総経路予算256購入を初期値とする。上限は待機時間の制限ではない。

解禁経路を採用した場合、予約先は最終Upgradeを保持し、毎周期その前提を再計算して一操作のみ実行する。解禁前にUpgrade購入APIを呼ばない。

## 比較条件

全合法候補の一手購入後価値を、同じ三期間で独立に記録する。その後、再利用可能なモデルだけを追加探索する。根の測定値しかない候補を複数手候補の価値だけで落とさないため、追加探索の先頭操作は、一手比較でも最良の測定限定候補以上である場合のみ最終選択へ参加できる。

解禁経路にも同じ先頭操作の制約を適用する。深い探索の結果が一手評価だけなら負ける測定限定候補を逆転させる場合は、探索結果を診断に残して選択から保留する。この保守性により本当に有利な経路を見送る可能性はあるが、未知の継続効果をゼロとして不当に不利にしない。

一手価値、追加探索価値、追加利益、制約による保留理由を分離して記録する。

## 予約再評価

pendingと購入可能な予約は保護する。資金待ち中だけ代替案を比較する。通常予約同士は一手価値、解禁予約は全費用を含む完成経路価値で比較し、比較種別を記録する。切替候補は共通の公平性制約を満たすものに限る。

旧予約に対する正規化スコア改善が絶対0.05かつ旧スコア絶対値の25%を超え、同じ代替目標が3回連続で優位なら切り替える。切替後4周期は再切替を抑制する。保護中も購入可能なら購入する。購入API失敗後の同一周期Fallbackは引き続き禁止する。

値は初期パラメータであり最適性の保証ではない。変化したクリック収益・Buff・新Upgradeは毎回の入力へ反映され、過去のスコアではなく同じ現在状態で比較する。

## 互換性と検証

engine=9.0.0-alpha.4、ruleset=cc-web-2.058/basic-2へ更新する。過去の実測JSONは書き換えず、旧エンジンをオフライン再生用に保存して旧版として再生する。新版で過去判断が一致したと偽装しない。

検証は解禁境界、複数前提、値上がり、予算、循環、実ゲーム形式のTierメタデータ、予約変更の連続確認・冷却・ready/pending保護、一手と複数手の逆転ケース、JSON往復決定性、従来回帰試験を含む。
