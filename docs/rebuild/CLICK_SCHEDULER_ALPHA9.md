# alpha.9 クリックタイマー遅延の補償

作成日: 2026-09-25。alpha.8からの差分。

## 症状と原因

目標を100回/秒にしても実クリック数が約40回/秒になる報告があった。従来は10ms周期のタイマー一回につき最大一回だけクリックしていた。このため、ブラウザのメインスレッド混雑やタイマー間引きで呼び出し間隔が約25msになると、目標値に関係なく約40回/秒が上限になった。

Game 2.058の通常クリック処理と、成功時だけ実測へ加える既存条件は機能している。問題はクリック要求のスケジュール側にある。

## 変更

前回のクリックタイマー処理からの経過時間をクリック枠として蓄積する。短い遅延が発生した場合は、一回の処理で不足分を補完する。

- 一回のタイマー処理で最大5クリック。
- 蓄積できる遅延は最大100ms。100msを超える停止では蓄積を破棄し、一回だけ実行する。
- 各クリックは従来どおりGameの通常クリック処理を一回ずつ呼ぶ。Cookieを直接加算しない。
- Gameが拒否したクリックは実測回数へ加えず、その回の残り補完も中止する。
- 自動化開始、観測モード切替、クリック速度変更、セーブ変更時は蓄積をリセットする。

25ms周期なら2回と3回を交互に実行し、平均100回/秒へ近づける。バックグラウンドタブから復帰した際に、停止時間分をまとめて実行することはない。

## 検証

自動試験135件、配布ビルド、全JavaScript構文、純粋層検査に合格。

- 10ms周期で100回/秒。
- 25ms周期を5秒続けた場合に99〜100回/秒。
- 100ms遅延時も一回の補完は5クリックまで。
- 長時間停止後は一回だけで、同時刻の再呼び出しでは追加しない。
- 100回/秒から20回/秒への変更後に過剰クリックしない。
- 拒否されたクリックを数えず、その補完バッチを停止する。
- alpha.8診断JSONを保存版Plannerで再生する。

テストは決定的な疑似時計とGameモックによる。ブラウザが非表示タブを長時間停止する場合、その期間の100回/秒は保証せず、安全のため補完しない。ユーザー指示に従い実ブラウザ確認は実施していない。
