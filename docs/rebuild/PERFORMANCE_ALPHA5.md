# alpha.5 購入評価と処理負荷の改善

## 報告と切り分け

ユーザー報告：未対応効果による待機が多く、動作が若干重い。UIでは該当Upgradeを特定できない。今回の実セーブ診断は未取得。以下はコードから特定した問題と合成fixtureによる検証であり、報告状態の完全再現ではない。

- 待機勝利時、購入不可も含む未知候補が1個あるだけで `WAIT_UNKNOWN_EFFECT` を表示する。
- `buyFunction` を一律禁止し、ストア再描画だけの処理も除外している。
- 通常のCookie倍率を単発差分として扱い、後続の施設購入との相乗効果を評価できない。
- 価格割引を収益差分測定だけでは検出できない。
- 探索ノードごとに経路全体を3期間それぞれ再演算し、変化しない証拠情報も含め状態を深くコピーする。

## 変更方針

1. 未対応・購入対象外の候補を名前と理由で表示。未知候補は保持するが既知候補の購入を止めない。採算上の待機と評価不能を区別する。
2. `cookieUpgrades` の定数powerは全体倍率として測定照合する。ストア更新のみのコールバックは厳密に確認して許可する。価格割引は生産効果と独立にモデル化し、割引後の買い物まで同じ資産指標で比較する。任意コールバックを仮想実行しない。
3. シミュレーションで書き換える部分だけコピーする。各期間の親ノードの価値を再利用し、最後の購入以降だけ積分する。将来イベントとバフの期限は維持する。取得測定の周期間キャッシュは使わず、変化の見落としを避ける。

原典は調査済み公式Web 2.058 `main.js`（`CalculateGains`、`Upgrade.getPrice`、`modifyBuildingPrice`、Upgrade定義）。名称翻訳・説明文には依存しない。GC出現頻度、研究、季節切替などの未実装効果を架空のCpSへ変換せず、対象名を表示する。

## 検証

修正前に待機表示、倍率・割引・コールバックの合成fixtureを追加。旧alpha.4エンジンを保存し、旧診断JSONの再生と最適化前後の比較に使う。イベント境界・保護額・実クリック・入力不変性・予約・失敗後の追加購入禁止を回帰検証。既存実測fixtureと追加合成状態で処理時間を比較する。ブラウザ確認はユーザーの明示依頼時のみ。

## 実装された効果の範囲

- `cookieUpgrades` に実体が登録され、powerが定数の候補は受動生産倍率へ変換。現在の実測増産・クリック差分と一致しなければ、従来の現在状態限定測定へ戻す。
- 内部辞書の同一オブジェクトを使い、Season savings、Toy workshop、Santa's dominion、Faberge egg、Fortune #100、Wrinkler ambergrisの価格・生産効果を扱う。これらの個別規則だけで問題を閉じず、共通の施設価格倍率・Upgrade価格倍率・未評価表示・コールバック検証へ分離した。
- 割引そのものに架空の収益は付与しない。割引後の購入費と実際の増産を比較する。予約中は、先に割引を買うことで予約先へのETAを縮められる場合も候補になる。
- 公式価格式の丸め前値を実際のgetPriceと照合する。照合できないUpgradeは価格変更後の子状態で除外し、推測価格で購入経路を伸ばさない。共通卵・希少卵の購入数依存価格はそれぞれ2倍・3倍の増加を別に反映する。
- 許可するコールバックは `Game.storeToRefresh=1` / `Game.upgradesToRebuild=1` の代入のみ。任意処理、転生、切替、Lump消費は引き続き対象外。GC頻度・研究・季節等の未実装効果は名前付きで明示する。

## 残る制約

自然GC・コンボ期待値、研究/季節の解禁モデルは未実装。Cookie powerが関数のもの、他要素との相乗効果、特殊購入処理は完全対応ではない。価格関数がCpS等で変化する候補や一時的な価格バフの終了についても子状態の厳密モデルは未完了。alpha.4の公平比較制約は保持しており、単発効果しか扱えない候補があると割引等の長期経路を保守的に保留し得る。診断DBの長期容量管理は今回の対象外。

UIには `coverage.unmodeledAffordable` / `unmodeled` / `disabled` の区分を反映する。待機表示が変わったことを未対応効果すべての購入対応と混同しない。ブラウザ確認は行っていない。
