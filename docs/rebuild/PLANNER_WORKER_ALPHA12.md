# alpha.12 周期停止とクリック不足の軽減

作成日: 2026-09-25。alpha.11の実画面報告を受けた修正。

## 症状と原因

alpha.11で状態取得の反復測定を削減した後も、要求・実クリックは約60回/秒で、一定周期の停止が残った。購入周期は1.5秒であり、同じメインスレッド上で複数手の戦略探索を同期実行していた。この間はクリックタイマー、ゲーム描画、UI更新も進まない。

## 変更

- 純粋関数であるPlannerを専用Web Workerへ移し、Game操作とクリックタイマーから分離する。
- Workerへ渡すのは確定済み入力だけとし、GameやDOMへは触れさせない。返却された判断も従来どおりExecutorが先頭1行動だけ実行する。
- Worker生成が利用できない環境では同期Plannerへ自動的に戻す。
- モード変更や再注入中に古いWorker結果が返っても、世代番号と起動所有権の確認後に破棄する。
- 可視タブの処理停止は最大2秒分までクリック枠を保持し、1回最大5クリックで徐々に補う。非表示タブや2秒を超える停止は1回へリセットする。
- UIに状態取得時間と戦略計算時間を分けて表示する。戦略計算時間はWorker内の所要時間を含む待ち時間であり、その間もメイン画面は動作できる。

## 検証

自動試験143件、配布ビルド、全JavaScript構文、純粋層検査に合格した。

- 1秒の可視タブ停止後に、最大5クリックずつ不足分を解消する。
- 非表示タブの1秒分は補完しない。
- Worker経由で判断を受け取り、終了時にWorkerを停止する。
- 既存の25msタイマー、Gameクリック拒否、再注入、購入排他の試験を維持する。
- alpha.11診断JSONを保存版Plannerで再生する。

ユーザー指示に従いブラウザ検証は実施していない。Workerがブラウザ側の制約で使用できない場合は同期処理へ戻るため、その環境では「戦略計算」中の停止が残り得る。
