# alpha.11 周期的な状態取得停止の軽減

作成日: 2026-09-25。alpha.10の実画面報告を受けた修正。

## 症状と原因

UIの要求回数と実クリック数がともに約50回/秒で、1秒前後またはそれ以下の間隔で一瞬停止するとの報告があった。要求自体が減るため、Game側のクリック拒否ではなくメインスレッド上のタイマー停止である。

購入判断は既定1.5秒周期でGame状態を取得する。従来は状態が変わっていない周期でも、全施設と表示中Upgradeを仮想購入し、候補ごとに`CalculateGains`を同期実行していた。この間はクリックタイマーもUIも実行できない。

## 変更

- 施設数、所持Upgrade、Buff倍率、実績数、Aura、季節、価格効果、ストア候補、主要ミニゲーム状態、生産倍率が同じ場合、前周期の限界生産測定を再利用する。
- Cookie所持量、累計生産、Buff残り時間、GCタイマー、研究残り時間、実クリック数、予約はキャッシュせず毎周期更新する。
- ロック中施設は購入候補でないため仮想購入しない。Thousand fingers系の非Cursor一個あたりクリック効果を取得する必要がある場合だけ、最初の非Cursor施設を測定する。
- 状態が変われば全キャッシュを破棄して再測定する。仮想状態復元と周期前後の署名検査は維持する。
- UIへ直近の状態取得時間を表示する。診断JSONにはキャッシュhit/missと実行した測定回数を保存する。

## 検証

自動試験140件、配布ビルド、全JavaScript構文、純粋層検査に合格。

- 初回取得では従来どおり候補を測定し、同じ状態の次回取得では`CalculateGains`を0回にする。
- キャッシュ利用中もCookie所持量と累計生産を最新値へ更新する。
- 施設数が変わると再測定する。
- ロック中施設を増やしても仮想生産計算回数を増やさない。
- 保存復元、未知効果、予約、Game 2.058 fixture、旧alpha.10診断再生を維持する。

キャッシュを外れる購入直後やBuff構成変化時には再測定が一度発生する。実ブラウザ確認はユーザー指示に従い実施していない。更新後はパネルの「状態取得」と「要求／実クリック」を合わせて確認できる。
