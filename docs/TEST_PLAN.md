# テスト計画

## 1. 必須fixture

### 序盤クリック系列

- 0 CookieからCursorを1個買う。
- Cursor 1個後、Upgrade ID 0へ貯蓄する。
- ID 0購入後、Cursorを追加せずID 1へ貯蓄する。
- Cursor 10個でID 2を優先評価する。
- 日本語表示でも同じ結果になる。

### Grandma

- Steel-plated rolling pinsは標準条件でGrandma 10個では次Grandmaが優位、11個前後でUpgradeが優位になる。
- Grandma 28個で未購入のまま施設を買い続けない。

### Factory

- Child laborはFactory 5個の解禁直後には必ずしも買わない。
- 標準条件でFactory 11個前後から次Factoryより有利になることを確認する。

### 一般Upgrade

- 価格500・増産50/秒のUpgradeと価格400・増産2/秒の施設ならUpgradeを選ぶ。
- 価格500・増産1/秒のUpgradeと価格400・増産20/秒の施設なら施設を選ぶ。
- 最安施設価格がUpgrade価格より安くてもROIでUpgradeが優位なら貯蓄する。
- `priority=false`、`critical=false`でも候補から除外しない。

### 予約

- 予約中に資金へ到達した周期は対象Upgradeだけを試行する。
- `buy()`失敗時に施設へFallbackしない。
- 例外時も予約を保持する。
- 目標ETAを短縮する先行購入だけ許可する。

### Fallback

- 通常候補生成が失敗しても自動購入が停止しない。
- 復帰候補を価格順で選ばない。
- 価格100・回収200秒と価格500・回収25秒なら後者を選ぶ。

## 2. テスト層

1. 純粋関数の単体テスト
2. Gameモック統合テスト
3. 保存済み状態スナップショットのリプレイテスト
4. 実ブラウザでの0 Cookieからのスモークテスト
5. 日本語・英語表示の比較
6. 旧版と新版の同時注入による単一起動テスト

## 3. 合格条件

- 同じスナップショットから常に同じ判断を返す。
- 判断には候補、効果量、回収時間、将来資産、ETA差、採用理由が含まれる。
- 購入後に再計画される。
- 報告済み全fixtureが回帰しない。
